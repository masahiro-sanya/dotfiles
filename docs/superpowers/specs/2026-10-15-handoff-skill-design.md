# 引き継ぎスキル（handoff）設計

## 目的

セッションを切り替えるときの引き継ぎから、確かめていない記述をなくす。
書く側は全項目を確かめてから書き、読む側は再開時に確かめ直してから作業に入る。

## 背景（実例）

- 2026-10-15 の引き継ぎに、確かめていない推測が 2 つ混ざり、どちらも外れていた。
  - 「`claude/settings.json` の差分は実行時の値だと思う」→ 実際は除去対象外の `modelSettings` で、コミットに混ざる差分だった。
  - 「light-skills はチーム共通の変更で pull が止まっている」→ 実際は本人の feature ブランチ上の未コミット作業だった。
- 同じ件の「pull が止まった日付」が memory の 2 ファイルで食い違っていた（8/27 と 10-13）。日付つきの引き継ぎファイルを増やす運用で、古い記述が残ったため。

## 決めたこと

| 項目 | 決定 |
|---|---|
| 結果がまだ出ていないもの（CI 実行中・返事待ち） | 今の状態を確かめ、その確認コマンドと結果を書く（例: `gh run view 123` で in_progress） |
| 書き先 | テーマごとに 1 ファイルを持ち、毎回上書きする |
| 読む側 | スキルに含める。再開時に確認コマンドを流し直す |
| 形 | スキル 1 つに「書く」「読む」の 2 モード。補助スクリプトと hook は作らない |

却下した案:

- 状態収集スクリプト: 対象のリポや確かめる内容が作業ごとに違い、保守が重い。
- SessionStart の hook で自動確認: hook は再開するテーマを判断できず、毎回無関係な確認が走る。

## 構成

- スキル本体: `claude/skills/handoff/SKILL.md`（`setup.sh` が skills をディレクトリごと `~/.claude/skills/` へ symlink する既存の仕組みに乗る）
- 呼び出し語
  - 書くモード: 「引き継ぎ」「セッション切り替え」「handoff」
  - 読むモード: 「〜の続き」「引き継ぎを読んで」
- 書き先: 作業中のプロジェクトの memory ディレクトリ（system prompt の Memory 節に書かれたパス）に `handoff-<テーマ>.md`
  - テーマ名は kebab-case の短い語（例: `handoff-harness.md`）。既存のファイルがあれば上書きする
  - 中身は最新の状態だけ。経緯は書かない（経緯は既存の記録用 memory に残す）
  - `MEMORY.md` に索引 1 行を置く。既にあれば書き換える

## 書くモードの手順

1. **挙げる**: このセッションで触ったものを会話から全部挙げる。対象はリポ・ブランチ・worktree・PR・memory・Notion / Slack 等の外部のページ・サブエージェントとバックグラウンドの処理。
2. **確かめる**: 挙げたもの 1 つずつに確認コマンドを流す。
   - リポ: `git status --short --branch`、`git log @{u}..HEAD --oneline`（上流が無ければその旨を結果に書く）、`git worktree list`、`git stash list`。未コミットの差分は `git diff` で中身を読み、何の変更かを 1 行で書く（差分そのものは貼らない。認証情報が混ざりうるため）
   - PR: `gh pr view <番号> --json state,reviewDecision,statusCheckRollup`
   - サブエージェント・バックグラウンド: 完了通知を受け取ったか。受け取っていなければ「完了通知なし」と書く
   - 外部のページ: 読み取りツールで再取得した結果
   - チームのリポも読み取りだけなら確かめる（`git status` 等）。変更はしない
3. **書く**: 次の形で書く。

   ```markdown
   ---
   name: handoff-<テーマ>
   description: <テーマ>の引き継ぎ（YYYY-MM-DD 時点）。再開時は handoff skill の「読む」で確認コマンドを流し直してから作業する
   metadata:
     type: project
   ---

   ## 現在の状態（YYYY-MM-DD HH:MM 確認）
   - <事実> — `<確認コマンド>` → <結果 1 行>

   ## 判断待ち
   - <ユーザーが決めること> — <判断材料の所在>

   ## 次の一手
   - <最初にやること>
   ```

   - 「現在の状態」の各行は事実・確認コマンド・結果の 3 つを必ず持つ。確認コマンドが書けない行は書かない
4. **走査する**: 本文に「と思う」「はず」「おそらく」「たぶん」「と思われる」「らしい」が残っていたら、その項目について手順 2 に戻る。確かめた結果で書き直すまで先に進まない。
5. **読み直す**: 書いたファイルを Read で読み直し、手順 1 で挙げたものが全部載っていること、索引の 1 行が更新されていることを確かめる。
6. **報告**: グローバルルールの「完了と言う前の 3 行」で締める。3 行目（確かめていないこと）は「なし」になる形で手順 2 を終えておく。

## 読むモードの手順

1. `MEMORY.md` から該当テーマの `handoff-<テーマ>.md` を探して読む。無ければ「引き継ぎファイルが無い」と報告して止まる（推測で再開しない）。
2. 「現在の状態」の確認コマンドを全部流し直す。
3. 書いてある結果と今の結果を突き合わせ、食い違いを作業に入る前に報告する。食い違いが無ければ「全項目一致」と 1 行で報告する。
4. 「判断待ち」をユーザーに示す。食い違いがあればユーザーの返事を受けるまで書き込みをしない。食い違いが無ければ「次の一手」から再開する。

## 範囲外

- 既存の引き継ぎ memory（`session-20261001-catchup-handoff.md` 等）の移し替え。
- 状態収集スクリプト・hook。

## 確かめ方

- writing-skills の手順で作る。スキルなしで引き継ぎを書かせて推測が混ざることを先に確かめ、スキルありで推測が消えることを見る。
- 最初の実例は今回の件（light-skills の状態と `claude/settings.json` の差分）で書くモードを試し、別セッションで読むモードを試す。
